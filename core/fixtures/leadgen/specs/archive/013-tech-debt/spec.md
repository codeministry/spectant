# 013 — The debt behind v0.5.0 is paid down without a change in behaviour

## Problem

Sixteen build steps and 163 commits in 24 days shipped v0.5.0 with a clean surface — no TODO
comment, no `any`, no skipped test, no lint suppression anywhere in the tree — and debt one
level below it. The three working-notes files stand at 95 %, 99 % and 94 % of the budget
`WorkingNotesStaySmallTest` holds them to; the next trap paragraph in `backend/CLAUDE.md` fails
`check`. `README.md` and `docs/DEVELOPMENT.md` still say the formatting gate is off, a state the
build left weeks ago. `.env.example`, the only contract a fresh clone has, lacks two placeholders
the shipped defaults read and carries one nothing reads. The compose stack starts `web` before
`api` answers, and neither has a healthcheck. The version is spelled in four files and the HTTP
user agent has been four minors stale on every page it fetched. Two listeners outlive the
component that added them. And the Lombok convention `backend/CLAUDE.md` states — `@Slf4j` for
the logger, `@RequiredArgsConstructor` where the constructor only assigns — was applied to 13 of
the 77 classes it fits and then stopped, which leaves 165 assignment lines and their signatures
saying nothing.

The audit that found these (2026-09-24, operator-local) scored 43 items. This spec takes the
ones that change no behaviour and cost an afternoon each. What it leaves stands under
`## Not yet specified` so it graduates into its own spec rather than into a note that ages.

## Out of Scope

- Every item that changes behaviour or a boundary: the model calls inside transactions, the run
  row `ScoreBatchCollector` leaves open, the Testcontainers 2.x migration, the enrichment
  silences, the stale-language computeds, the catalog cache, the controller advice, the test
  coverage of the scoring core, the package cycles, the large-class splits. All fog below.
- The 27 `UncheckedIOException` wrappers: whether `@SneakyThrows` or a functional helper
  replaces them changes what a stack trace names, and the operator wants that as its own
  decision (context.md, round 1).
- `@Getter`: the hand-written accessors the survey counted compute a value (`removedTotal`,
  `passRate`, three `Optional`s) and are not field getters. Measured before minting; no claim.
- Git-state hygiene (empty worktrees, stale branches, stale jars under `build/`) — local to one
  machine, not a property of the repository.
- The version mechanism: `LEADGEN_VERSION` from the image tag over a literal default, no build
  info in the jar. The operator keeps it as it is so the service stays AOT-compatible for
  GraalVM, and that constraint binds every other claim transitively (ISC-350).
- Any new endpoint, field, migration or configuration key. ISC-350 forbids it.

## Goal

The afternoon-sized debt is paid: the three working-notes files sit at or under 85 % of their
budget with the reasoning moved to `docs/decisions/`, no document claims a gap the build has
closed, `.env.example` and the placeholders are held equal by a test, the compose stack reports
three healthy services, the two leaks are closed, the catalog literals are keys, and every backend class whose
constructor only assigned its fields carries `@RequiredArgsConstructor` — with every request
mapping, response field, migration and configuration key meaning exactly what it meant before,
and the service as AOT-compatible for GraalVM as it is today.

## Decisions

- **2026-09-24 — ISC-341: the web image goes non-root on 8080, and the office chart follows.** Asked before T6: a non-root nginx cannot bind :80, and the deployment chart outside this repository sets the container port from a value and ships its own `listen 80` ConfigMap. The operator chose the unprivileged image on 8080 over keeping :80 (drop the clause) or `setcap` (a hand-rolled image). Consequence, recorded in the master's Remaining Work: the chart's web port value and its nginx ConfigMap move to 8080 before the next deploy of that image; until then the office instance would deploy a web pod whose readiness never answers. Compose and `nginx.conf` move in this repository with T6.
- **2026-09-24 — Second look on the sweep: a NUL byte had hidden a class, five constructors were left out, adopted; the threshold is 31.** `QueryEmbedder` carried a raw 0x00 inside a char literal, so `rg` read the file as binary and neither the sweep nor the probe saw its assignment-only constructor; the byte is the escape `'\0'` now, the class is swept, and the probe runs with `-a`. Five more `JdbcClient.create(dataSource)` constructors outside the candidate list (`LastRunQueryService`, `PageCache`, `SimilarOffers`, `BlockLabelStore`, `ScoreWriter`) and the nested enum `ConfigurationBanner.Origin` are swept too; `JdbcClient.create` is down to 7, each beside other constructor work. Counted binary-safe the baseline was 171, not 165. A stale comment in `IngestOrderTest` about the map that no longer exists stays, because the claim forbids a test edit; it goes with the next test change.
- **2026-09-24 — refined: ISC-346's threshold is 32, and the connector lookup keeps its startup refusal.** With the `JdbcClient` injected the sweep took 50 classes and left 32 assignments (from 165), every one in a constructor the rule keeps out: five that build a `TransactionTemplate`, a mapper, a `JdbcTemplate` or a FreeMarker configuration beside the client (`PackagingService`, `ContentService`, `CoverLetterService`, `FilterService`, `OfferStore`), eight that do work (`AdFetcher`, `RuleScorer`, `ConfigLoader`, `ConfigRegistry`, `ConfigWatcher`, `ManualInbox`, `AnthropicJudge`, `CoverLetterGuard`), two with a sibling constructor (`StageLog`, `FetchWindow`), two that call `super`, one a test hand-builds (`PipelineRunRecorder`), one nested class outside the list. The 25 was a guess before the rule existed; 32 is what the rule leaves, and the claim now says why each line stays. One behaviour the sweep would have lost was restored by the parent: two connectors with one `type()` used to fail the context in `Collectors.toMap`, and a list lookup would let the first win in silence — a `@PostConstruct` guard refuses the same case at the same moment. Turning the four remaining builders into beans is Phase 2 fog, not this spec.
- **2026-09-24 — refined: ISC-346 injects the `JdbcClient` and drops the `SourceConnectors` bean.** The sweep under its strict rule (assignments only) took 27 classes and left 104 assignments, not 25: about 25 classes do exactly one other thing in their constructor, `this.jdbc = JdbcClient.create(dataSource)`, and `IngestOrderTest` builds `IngestService` with a connector list, so a `SourceConnectors` parameter would have forced the test edit the claim forbids.
